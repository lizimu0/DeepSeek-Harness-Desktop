## 2026-09-24 核心升级到 0.1.7-rc.1

版本事实：`0.1.7-rc.1`（9-23 发布）在 **next** 通道；npm 的 `latest` 仍是 `0.1.5-rc.3`，所以 `npm i -g @deepseek-ai/dsh` 默认装到的不是 0.1.7。本次按用户要求显式安装 0.1.7-rc.1。

升级中发现并修复的兼容问题：

1. **会话格式升到 v4**：`stats.js` 原先只接受 v0–v3，新会话会被判为不支持。已放宽到 v4（v4 仅改消息来源标识、子代理目录与 `request/header.system` 退役，计量事件与 seq 布局未变），并新增 v4 回归用例；比 v4 更新的代际仍显式拒绝而不是猜测。
2. **设置文件迁移**：0.1.7 把 `settings.yaml` 导入到 profile 的 `cordis.patch.yml`，原文件改名为 `settings.yaml.imported`。余额插件原先只读旧文件，导致供应商从 8 个跌到 1 个。现在按「官方服务 → profile 补丁文档 → 旧 settings.yaml → .imported」顺序读取，任一来源不可读都会继续尝试下一个。
3. **settings 服务接口变更**：新版不再提供 `get(命名空间)`。原实现遇到不认识的接口会直接抛 `settings-unavailable`（HTTP 503），现已改为回退到文档而不是报错。
4. **第三方插件**：任务看板在 0.1.7 上等待已移除的 `settingsScope` 服务而无法激活（按用户要求已删除该插件）；Git 图升级到 0.4.1 以匹配新核心。
5. **卡片文案**：按状态区分为余额数值 /「非余额」（计费上限）/「无接口」（无公开余额 API）/「无密钥」/「离线」，不再一律显示「不可用」。

本轮验证：`npm run verify` 108 项通过；用真实 9-bundle 组合（含第三方插件）在隔离 home 启动 0.1.7 无插件加载错误；真实应用侧栏显示「stepfun 无接口」，统计读取 278.9M tokens 且状态 ok。
